Vou separar em 3 partes bem diretas:

O que é a aba SINAN x a aba FORMULÁRIOS

Como estão funcionando esses formulários hoje (por baixo dos panos)

Passo a passo pra deixar TODOS os formulários iguais aos oficiais do SINAN por agravo

1. Aba SINAN x aba Formulários

Aba SINAN (menu da esquerda)
É onde o usuário da unidade vai:

Escolher um paciente

Escolher um agravo (Dengue, TB, Hanseníase etc.)

Preencher a notificação usando o template daquele agravo

Ou seja: é a parte operacional, de uso diário.

Aba Formulários → categoria SINAN
É o “estúdio de templates”.
Cada item da lista (Dengue A90, Chikungunya A92.0, etc.) é um template de formulário SINAN que define:

quais campos existem

tipo do campo (texto, número, data, select…)

se é obrigatório ou não

validações extras

Quando você cria uma “Nova notificação” lá na aba SINAN, o sistema:

vê qual agravo foi escolhido

carrega o template da aba Formulários correspondente

monta a tela de preenchimento em cima disso

Então:

Aba Formulários = onde você deixa tudo 100% fiel ao SINAN
Aba SINAN = onde a equipe usa esses templates pra registrar o caso.

2. Como esses formulários funcionam hoje (conceito)

Pelo que aparece nos prints:

Cada formulário SINAN (Dengue A90, TB, Hanseníase, etc.) é um template “built-in” marcado com o selo vermelho SINAN.

Ao abrir o template (ex.: Dengue (A90)) você vê:

Campos do Formulário – lista de campos (Tipo de Notificação, Agravo/Doença, UF, Município de Notificação, etc.)

Embaixo, a área “Testar Validação” com um JSON de exemplo.

Isso indica que:

O template está definido no código (TypeScript/JSON) – essa tela é só de visualização e teste, não é um construtor drag-and-drop.

Cada campo tem:

uma chave interna (ex.: tipo_notificacao, agravo, cid10, dt_notific, municipio_notificacao_ibge etc.)

um rótulo (o que aparece pro usuário)

um tipo (text, number, date, select…)

flag de obrigatório

às vezes um domínio de valores (para selects: sexo, escolaridade, zona, etc.)

Quando você cola o JSON em “Testar validação” e clica Validar, o backend verifica:

se todos os obrigatórios estão preenchidos

se tipos e formatos estão corretos (datas válidas, número, etc.)

3. Como EDITAR e deixar TODOS os formulários idênticos ao SINAN
3.1. Visão geral do que você precisa fazer

Pra cada agravo (Dengue, TB, Hanseníase etc.), você vai:

Olhar a ficha oficial do SINAN (PDF da ficha + instrucional).

Montar a lista de campos: nome, tipo, se é obrigatório, opções (quando for select).

Editar o template desse agravo no código (arquivo TypeScript/JSON) para:

ter todos os campos da ficha

com o mesmo significado e códigos que o SINAN usa

Usar a tela “Dengue (A90) → Testar validação” pra conferir se a validação está ok.

3.2. Onde editar (no código)

Dentro do seu projeto no Replit, os templates provavelmente estão em algo como:

shared/ ou server/

pastas tipo forms/, formTemplates/ ou sinan/

O caminho prático:

No Replit (lado direito) clique na lupa de busca.

Pesquise por: "Dengue (A90)"

O arquivo onde aparecer esse texto é o template de formulário da Dengue.

Lá dentro você deve ver algo parecido com (exemplo de estrutura, adaptado):

export const dengueA90Form = defineFormTemplate({

  nome: 'Dengue (A90)',
  slug: 'dengue',

  fields: [
    {
      key: 'tipo_notificacao',
      label: 'Tipo de Notificação',
      type: 'select',
      required: true,
      options: [
        { value: '1', label: 'Rotina' },
        { value: '2', label: 'Surto' },
      ],
    },
    {
      key: 'agravo',
      label: 'AgravO/Doença',
      type: 'text',
      required: true,
    },
    {
      key: 'cid10',
      label: 'Código CID-10',
      type: 'text',
      required: true,
    },
    {
      key: 'dt_notificacao',
      label: 'Data da Notificação',
      type: 'date',
      required: true,
    },
    {
      key: 'semana_epidemiologica',
      label: 'Semana Epidemiológica',
      type: 'number',
      required: false,
    },
    // ... e assim por diante (mais 40+ campos)
  ],
});


O que você precisa fazer é completar/ajustar esse array fields pra ficar idêntico à ficha oficial do agravo.

3.3. Como montar cada formulário igual ao SINAN (passo a passo)

Vou usar Dengue (A90) como exemplo, mas é a mesma lógica pros outros.

Passo 1 – Abra a ficha oficial

Abra a ficha de Dengue no PDF das fichas do SINAN (aquele FICHAS.zip que você tem).

Identifique os blocos:

Dados de Notificação

Dados do Paciente

Dados de Residência

Dados Clínicos/Laboratoriais

Encerramento etc.

Passo 2 – Monte um “mapinha” de campos

Num rascunho (ou planilha), faça algo assim:

Grupo	Campo na ficha	Código SINAN (se existir)	Tipo	Obrigatório
Notificação	Tipo de Notificação	TP_NOT	select	Sim
Notificação	Agravo/Doença	ID_AGRAVO	select	Sim
Notificação	CID-10 principal	CID_PRINCIPAL	text	Sim
Notificação	Data da Notificação	DT_NOTIFIC	date	Sim
Notificação	Semana Epidemiológica	SEMEP	number	Não
Notificação	UF	SG_UF_NOT	select	Sim
Notificação	Município Notificação	ID_MUNICIP	select	Sim
Notificação	Código IBGE	ID_MUNICIP	text	(derivado)
Notificação	Unidade de Saúde	NM_UNIDADE	text	Sim
Notificação	CNES	CO_CNES	text	Sim
Paciente	Nome completo	NM_PACIENT	text	Sim
Paciente	Sexo	CS_SEXO	select	Sim
…	…	…	…	…

Os códigos (TP_NOT, DT_NOTIFIC etc.) vêm do manual / dicionário de dados, mas se você ainda não usar os códigos oficiais como key, pelo menos use um nome interno consistente.

Passo 3 – Traduzir isso pro template de formulário

Dentro do arquivo do template, crie um campo para cada linha dessa tabela. Exemplo:

fields: [
  {
    key: 'TP_NOT',
    label: 'Tipo de Notificação',
    type: 'select',
    required: true,
    options: [
      { value: '1', label: 'Rotina' },
      { value: '2', label: 'Surto' },
      { value: '3', label: 'Outros' },
    ],
  },
  {
    key: 'DT_NOTIFIC',
    label: 'Data da Notificação',
    type: 'date',
    required: true,
  },
  {
    key: 'ID_MUNICIP',
    label: 'Município de Notificação',
    type: 'text', // ou select se você buscar da tabela de municípios
    required: true,
  },
  {
    key: 'CO_CNES',
    label: 'Código CNES',
    type: 'text',
    required: true,
  },
  // ... todos os demais
]


Importante:

Campos que o SINAN usa como obrigatórios mínimos (número da notificação, data, município, agravo, nome, data de nascimento/idade, sexo, data início sintomas) têm que ser required: true.

Campos que são obrigatórios só em alguns agravos, você marca required: true no template daquele agravo.

Passo 4 – Validar com o JSON

Na parte “Testar validação” do modal (embaixo na tela do Dengue):

Monte um JSON com as chaves exatamente como você colocou no template:

{
  "TP_NOT": "1",
  "DT_NOTIFIC": "2025-12-05",
  "ID_MUNICIP": "2910057",
  "SG_UF_NOT": "BA",
  "CO_CNES": "1234567",
  "NM_PACIENT": "FULANO DE TAL",
  "CS_SEXO": "1",
  "DT_NASC": "1990-01-10",
  "DT_SIN_PRI": "2025-12-03"
  // ... demais campos
}


Clica em Validar.

Se algum campo obrigatório estiver faltando, o sistema deve indicar erro – isso ajuda a você ajustar o template.

3.4. Replicando para TODOS os agravos

O fluxo pra fechar o pacote de 33 fichas SINAN que você tem aí:

Na aba Formulários → filtro categoria = “SINAN – Notificações”

Pega um agravo por vez: Dengue, Chikungunya, Zika, Meningite, TB, etc.

Pra cada um:

Abre a ficha oficial (PDF)

Preenche a tabelinha de campos

Edita o arquivo de template correspondente no código

Testa com o JSON na própria tela de validação

Quando todos os templates estiverem fechados:

Qualquer formulário preenchido na aba SINAN já vai sair:

com todos os campos que o SINAN exige

pronto para o digitador transferir pro SinanNet sem ficar “inventando” nada

Se você quiser, posso montar um modelo completo de fields para um agravo específico (ex.: Dengue) já com a sugestão de key, tipo e obrigatório, pra você só colar no arquivo do template e ir adaptando pro padrão exato do seu código.
