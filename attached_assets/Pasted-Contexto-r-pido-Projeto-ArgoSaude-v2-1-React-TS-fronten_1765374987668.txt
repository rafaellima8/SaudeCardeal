Ações técnicas detalhadas — ordem e expectativas (execute em ordem e pare se encontrar risco >MÉDIO sem pedir aprovação):

PHASE A — INVESTIGAÇÃO E CORREÇÃO RÁPIDA (SAFE)
1. Diagnóstico do erro JSON (alto impacto)
   - Inspecione logs do servidor (dev/prod) e console do browser ao reproduzir: capture a request que retorna HTML em vez de JSON. (Suspeita: rota retornando HTML 500/404 ou middleware de autenticação redirecionando para login HTML.)
   - Arquivos para checar (prioridade): `client/src/services/api.ts` (fetch wrapper/axios), `server/routes.ts`, `server/middlewares/*` (auth, enforceUnitScope), handlers TFD (`server/services/tfd`), unidades (`server/services/units`), sinan export (`server/services/sinan`).
   - Verifique `fetch`/`axios` chamadas que esperam `application/json` e routes que usam `res.sendFile()` ou `res.render` indevidamente.
   - Fix requerido: garantir que todas as API endpoints chamadas por frontend retornem `res.json(...)` e status corretos, e que erros sejam JSON `{ error, message }`. Remova redirecionamentos HTML em APIs — se auth redireciona, em APIs deve retornar 401 JSON.

2. Patch rápido (non-destructive)
   - Add wrapper middleware `ensureJsonResponse` (aplicar temporariamente em `/api/*`) que converta respostas de erro HTML em JSON (com stack trace curto em dev). Exemplo:
     ```ts
     function ensureJsonResponse(req,res,next){
       res._send = res.send;
       res.send = function(body){ 
         if (typeof body === 'string' && body.trim().startsWith('<')) {
           res.type('application/json');
           return res._send.call(this, JSON.stringify({ error: 'server_html_response', body: body.slice(0,400) }));
         }
         return res._send.call(this, body);
       }
       next();
     }
     ```
   - Deploy essa correção como canary para que front não quebre e para coletar stack traces completos.

PHASE B — CORREÇÕES POR BUG
3. **TFD - Criar Solicitação**
   - Reproduza via E2E test: preencher modal, submeter e validar resposta 201 + location. Capture payload e rota (`/api/tfd/create` ou similar).
   - Corrija handlers: validar `Content-Type` no servidor; quando receber JSON parse error, log e retornar 400 JSON.
   - Confirmar que front envia `fetch(url,{headers: {'Content-Type':'application/json'}, body: JSON.stringify(payload)})`.
   - Adicionar testes unitários para validar schema do request (zod) e testar falhas de parsing.

4. **Unidades - Nova Unidade**
   - Mesmo padrão: identificar handler, checar validações schema (zod/yup). Se o servidor redireciona ao login (HTML), alterar para 401 JSON.
   - Atualizar response para retornar a unidade criada em JSON e atualizar cache do frontend (TanStack Query `invalidateQueries('units')`).

5. **SINAN - Imprimir Ficha & Exportar DBF**
   - Imprimir ficha: checar se frontend chama `/api/sinan/print/:id` que devolve PDF ou HTML. Se PDF: `res.setHeader('Content-Type','application/pdf'); res.send(Buffer)`. O toast indica JSON parse error -> talvez frontend faça `response.json()` ao invés de `response.blob()` ou `response.arrayBuffer()`.  
     *Fix*: no frontend, quando endpoint retorna PDF, use `fetch(...).then(r => r.blob()).then(blob => createObjectURL(blob))`. Ajustar função `printSinan` e adicionar um util `downloadOrOpenBlob`.
   - Export DBF: verificar rota `/api/sinan/export/dbf` — certificar que responde com `application/octet-stream` e `Content-Disposition: attachment; filename="sinan.dbf"`. No frontend, usar `response.blob()` e forçar download. Se endpoint atual retorna HTML de erro, aplicar `ensureJsonResponse` e corrigir server logic.
   - Adicionar unit/integration tests: mock responses e assegurar frontend usa blob API.

PHASE C — MODEL & VALIDATION CHANGES (LOW RISK)
6. **Profissionais - CNS opcional**

   - Frontend: no form `client/src/pages/profissionais/*` remover `required` do campo e do HTML, ajustar mensagens.
   - Tests: unit test validação aceitando sem CNS; E2E cria profissional sem CNS e checa sucesso 201.

PHASE D — RBAC E FLUXOS (REVIEW)
7. Auditoria de Permissões

PHASE E — TESTES & CI

10. Rollback scripts (para cada migration/alteração):
