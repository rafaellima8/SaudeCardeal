Quero que você implemente, no meu SaaS de saúde municipal (módulo médico / e-SUS), uma funcionalidade de encaminhamento inteligente:
quando o médico da UBS estiver criando um encaminhamento, o sistema deve sugerir automaticamente a especialidade ideal com base nas informações da consulta.

🔧 Contexto técnico do projeto

Tipo de sistema: SaaS multi-tenant para gestão de saúde municipal (e-SUS / APS / PEC Integrado).

Módulo atual: Módulo Médico (consultas + encaminhamentos).

Stack (assuma isso, se não existir ainda você pode ajustar/criar o básico):

Backend: Node.js + Express + TypeScript

Banco: PostgreSQL usando Drizzle ORM (ou outro ORM se detectar no projeto)

Autenticação: JWT multi-tenant com tenantId (se necessário, só manter padrão existente)

Já existe:

Entidade / tabela de paciente;

Entidade / tabela de usuário médico;

Entidade / tabela de consulta ou registro clínico;

Alguma noção de encaminhamento (se não existir, você pode propor/implementar o modelo).

Se encontrar uma estrutura diferente no repositório, adapte, mas mantenha a ideia: encaminhamento médico com sugestão de especialidade.

🧠 Objetivo funcional

Quando o médico da UBS for registrar um encaminhamento, ele vai informar (no mínimo):

pacienteId

medicoId

motivoEncaminhamento (texto livre, ex.: “dor lombar crônica há 3 meses”, “suspeita de hipotireoidismo”)

hipoteseDiagnostica (texto livre ou código CID, se existir)

Alguns campos estruturados (se já existirem), por exemplo:

sinaisAlarme (booleanos, ex.: febre alta, perda de peso, sangramento, etc.)

tipoAtendimento (agudo, crônico, acompanhamento, etc.)

Com base nisso, o sistema deve:

Sugerir uma ou mais especialidades com um score de relevância.

Indicar a especialidade mais provável no topo.

Explicar o porquê (ex.: “palavra-chave ‘hipotireoidismo’ encontrada → endocrinologia”).

Endocrinologia

🗄️ 1. Modelagem de dados

Crie / ajuste as tabelas necessárias para suportar essa inteligência.

Tabela especialidades

id (PK)

nome (string – ex.: “Endocrinologia”)

slug (string – ex.: “endocrino”, “cardiologia”)

descricao (opcional)

ativo (boolean)

Tabela regras_encaminhamento (base de regras configuráveis)

id (PK)

especialidadeId (FK -> especialidades)

palavrasChave (array/texto, ex.: ["hipotireoidismo", "tireoide", "diabetes"])

cidRelacionados (array/texto, ex.: ["E11", "E03"]) – se o sistema já usar CID; se não, deixe opcional

pesoBase (número, ex.: 10, 20 etc. – para calcular score)

observacoes (texto livre)

Tabela encaminhamentos (se ainda não existir)

id (PK)

pacienteId (FK)

medicoId (FK)

especialidadeSugeridaId (FK -> especialidades, opcional, caso médico aceite sugestão)

especialidadeEscolhidaId (FK -> especialidades)

motivoEncaminhamento (texto)

hipoteseDiagnostica (texto ou código)

dadosComplementares (JSONB para guardar sinais, escores, etc.)

status (enum: pendente, agendado, concluido, etc.)

createdAt, updatedAt

Use Drizzle (ou o ORM existente) para criar esses modelos e a migration correspondente.

🧮 2. Motor de sugestão de especialidade (rule-based)

Implemente um serviço central, por exemplo:

Arquivo sugerido: src/services/encaminhamento/sugestorEspecialidade.ts

Função principal (exemplo):

async function sugerirEspecialidades(input: {
  motivoEncaminhamento: string;
  hipoteseDiagnostica?: string;
  cid?: string;
  dadosComplementares?: any;
}): Promise<Array<{
  especialidadeId: string;
  nome: string;
  slug: string;
  score: number;
  justificativa: string;
}>>


Regras básicas do motor (pode melhorar, mas comece assim):

Carregar todas as regras_encaminhamento + especialidades.

Normalizar texto de entrada (motivoEncaminhamento, hipoteseDiagnostica):

Tudo minúsculo,

Remover acentos,

Dividir em tokens/palavras.

Para cada regra:

Se alguma palavraChave aparece no texto → soma pesoBase ao score da especialidade.

Se o cid da entrada bater com algum cidRelacionados → soma peso extra.

Calcular um score final por especialidade.

Ordenar as especialidades por score (descendente).

Retornar apenas as que tiverem score > 0.

Montar campo justificativa textual, exemplo:

“Encontrado termo ‘hipotireoidismo’ no motivo do encaminhamento (regra Endocrino).”

“CID E11 corresponde à regra de Endocrinologia (Diabetes Mellitus).”

Se não houver nenhuma regra batendo, retornar lista vazia ou uma indicação de que nenhuma especialidade foi sugerida.

🧪 3. Endpoint de sugestão de especialidade

Crie um endpoint REST para o módulo médico:

Método: POST

Rota sugerida: /api/encaminhamentos/sugerir-especialidades

Corpo da requisição (JSON):

{
  "motivoEncaminhamento": "dor lombar cronica ha 3 meses, com irradiação para perna direita",
  "hipoteseDiagnostica": "provavel radiculopatia lombar",
  "cid": "M54.5",
  "dadosComplementares": {
    "sinaisAlarme": {
      "perdaPeso": false,
      "febre": false,
      "traumaRecente": false
    }
  }
}


Resposta (JSON):

{
  "sugestoes": [
    {
      "especialidadeId": "ortopedia-id",
      "nome": "Ortopedia",
      "slug": "ortopedia",
      "score": 42,
      "justificativa": "Palavra-chave 'lombar' e CID M54.5 associadas à regra de Ortopedia."
    },
    {
      "especialidadeId": "geriatria-id",
      "nome": "Geriatria",
      "slug": "geriatria",
      "score": 15,
      "justificativa": "Regra de Geriatria para dor crônica em idosos (se aplicável)."
    }
  ]
}


Esse endpoint será usado pelo front-end quando o médico estiver preenchendo o formulário de encaminhamento.

🩺 4. Integração com criação de encaminhamento

No endpoint já existente de criação de encaminhamento (ex.: POST /api/encaminhamentos), faça:

Não obrigue a usar a sugestão, mas:

Se vier especialidadeId vazio do front, você pode:

Chamar internamente o serviço sugerirEspecialidades,

Preencher especialidadeSugeridaId com a primeira da lista,

E deixar para o front exibir/confirmar em próxima tela.

Se o front já mandar a especialidade escolhida pelo médico:

Grave em especialidadeEscolhidaId.

Grave as sugestões e o histórico, se achar interessante (por enquanto, pode só armazenar a escolha final e o especialidadeSugeridaId).
