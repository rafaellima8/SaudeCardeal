3. Padronize a estrutura de templates de formulários SINAN

Crie (ou ajuste, se já existir) um módulo central de definição de templates SINAN, algo como:

shared/sinan/forms.ts
ou

shared/forms/sinan/index.ts

Nele, defina uma estrutura clara, por exemplo:

export type SinanFieldType = 'text' | 'number' | 'date' | 'select' | 'checkbox' | 'radio' | 'textarea';

export interface SinanFieldOption {
  value: string;
  label: string;
}

export interface SinanField {
  key: string;              // ex.: 'DT_NOTIFIC'
  label: string;            // ex.: 'Data da Notificação'
  type: SinanFieldType;
  required?: boolean;       // se é obrigatório para o SINAN
  options?: SinanFieldOption[]; // para selects / radios
  group?: string;           // ex.: 'Dados da Notificação', 'Dados do Paciente'
  helpText?: string;        // instrução resumida (quando estiver disponível no manual)
}

export interface SinanFormTemplate {
  id: string;               // ex.: 'sinan_dengue_a90'
  nome: string;             // ex.: 'Dengue (A90)'
  slug: string;             // ex.: 'dengue'
  categoria: 'SINAN';
  cid10: string;            // ex.: 'A90'
  pagina?: { width: number; height: number }; // tamanho do PDF da ficha
  versaoFicha?: string;     // ex.: 'NINDIV_v5', 'DENGUE_2015'
  agravoCodigo?: string;    // código do agravo usado internamente
  fields: SinanField[];
}


E tenha uma coleção central:

export const SINAN_FORM_TEMPLATES: SinanFormTemplate[] = [
  dengueTemplate,
  chikungunyaTemplate,
  zikaTemplate,
  // ... todas as outras fichas
];


Certifique-se de que a tela “Formulários Digitais → categoria SINAN” consome essa lista central.

Para cada template de agravo:

Abra a ficha oficial no FICHAS.zip e liste todos os campos na ordem em que aparecem na ficha, incluindo grupos (dados de notificação, dados do paciente, dados de residência, dados clínicos, laboratoriais, encerramento).

Para cada campo, defina:

key (de preferência, igual ou muito próxima ao código SINAN, se existir)

label (texto da ficha)

type (text, number, date, select, etc.)

required (true/false, de acordo com o manual e campos mínimos para o SINAN)

options (quando o campo é de múltipla escolha, seguindo os códigos oficiais)

group para organizar visualmente a ficha.

Garanta que os campos mínimos obrigatórios para entrar no SINAN (segundo o manual de Normas & Rotinas) estejam sempre com required: true, por exemplo:

Número da notificação (se for usado internamente)

Data da notificação (DT_NOTIFIC)

Município de notificação (ID_MUNICIP)

Agravo (ID_AGRAVO)

Data dos primeiros sintomas (DT_SIN_PRI ou equivalente)

Nome do paciente (NM_PACIENT)

Data de nascimento ou idade (DT_NASC ou idade + unidade)

Sexo (CS_SEXO)

Para selects com códigos, defina options usando os valores e rótulos oficiais (ex.: sexo, escolaridade, raça/cor, zona, tipo de notificação, etc.).

Se algum campo da ficha física for apenas anotação ou área livre não usada no SINAN, pode ser omitido — mas sempre priorize estar o mais fiel possível ao que realmente é lançado no sistema.

5. Integração com a aba SINAN (fluxo de uso)

Ajuste/garanta o seguinte fluxo:

Na aba SINAN, ao criar uma nova notificação:

O usuário escolhe o agravo (por nome ou CID-10).

O sistema encontra automaticamente o template SINAN correspondente em SINAN_FORM_TEMPLATES.

É carregado o formulário com todos os campos definidos nesse template.

Pré-preenchimento:

Campos de paciente (nome, CPF, CNS, data de nascimento, sexo, endereço) devem ser pré-preenchidos a partir do cadastro de pacientes, quando disponíveis.

Campos de unidade notificadora (nome da unidade, CNES, município, UF) devem ser preenchidos automaticamente a partir do contexto da conta/unidade logada, mas ainda permitindo edição se necessário.

Validação “Modo SINAN” ao salvar:

Antes de permitir “Concluir / Marcar como pronta para digitação no SINAN”, o backend deve:

Validar todos os campos required: true.

Validar formatos básicos (data válida, número, etc.).

Em caso de erro, retornar mensagem clara indicando quais campos estão faltando ou inválidos.

Armazenamento:

Salvar o preenchimento em uma tabela/estrutura especificamente para notificações SINAN, vinculadas ao paciente e ao agravo.

Armazenar também qual template/versão de ficha foi usado (versaoFicha) para compatibilidade futura.

6. Teste de validação via JSON (no modal do formulário)

Na tela de detalhe de cada template (onde aparece “Testar validação”):

Garanta que o backend tenha um endpoint/handler que receba:

templateId (ou slug)

payload JSON com os dados de exemplo

Execute o mesmo mecanismo de validação utilizado na criação de notificação real.

A resposta deve indicar:

ok: true se todos os obrigatórios e formatos estiverem corretos.

ok: false + lista de erros por campo (fieldKey, message) se houver problemas.

Isso é útil para o administrador testar cada ficha sem precisar criar notificações reais.
