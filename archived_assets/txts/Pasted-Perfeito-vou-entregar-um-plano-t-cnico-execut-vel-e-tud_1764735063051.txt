1 — Resumo da solução

Objetivo: transformar cada PDF do link (todas as fichas SINAN / dicionários) num template visual (imagem de fundo + caixas de campos) que o usuário preenche eletronicamente usando a mesma aparência do formulário em papel.

Funcionalidades principais:

formulário com o layout exato (fundo PDF/PNG) e inputs posicionados;

validação obrigatória por campo (regras do dicionário do estado);

rascunho, validação server-side, dedupe leve, fila de aprovação (Unidade → Vigilância → CPD);

geração de PDF final idêntico (mesma fonte/posicionamento) e exportação no layout exigido (TXT/CSV) quando necessário;

alertas por prazos e pendências;

relatórios para captação e indicadores;

não altera tabelas críticas do sistema sem flag de migração.

3 — Modelo de dados (novas tabelas, non-destructive)
-- sinan_forms: tabela de templates (meta)
CREATE TABLE sinan_templates (
  id uuid PRIMARY KEY DEFAULT gen_random_uuid(),
  name text NOT NULL,
  slug text NOT NULL UNIQUE,
  pdf_path text,        -- local do pdf original
  thumbnail_path text,  -- imagem para preview
  template_json jsonb,  -- coordinates, fields definition
  version integer DEFAULT 1,
  created_at timestamptz DEFAULT now(),
  updated_at timestamptz DEFAULT now()
);

-- drafts (formulários preenchidos mas não finalizados)
CREATE TABLE forms_drafts (
  id uuid PRIMARY KEY DEFAULT gen_random_uuid(),
  template_id uuid REFERENCES sinan_templates(id),
  unit_id uuid,
  created_by uuid,
  payload jsonb,        -- valores do form
  validation jsonb,     -- resultado da validação
  status text DEFAULT 'draft', -- draft|validated|sent|approved|rejected
  created_at timestamptz DEFAULT now(),
  updated_at timestamptz DEFAULT now()
);

-- workflow entries (aprovacoes)
CREATE TABLE forms_workflow (
  id uuid PRIMARY KEY DEFAULT gen_random_uuid(),
  draft_id uuid REFERENCES forms_drafts(id),
  action_by uuid,
  action text, -- submit|approve|reject|request_info
  comment text,
  created_at timestamptz DEFAULT now()
);


Nota: se preferir, mantenho essas tabelas nomeadas com sinan_ prefix para evitar colisão.

5 — Fluxo de criação do template (automático/supervisionado)

Upload/Download do PDF (a partir do link que você indicou ou upload manual).

Gerar imagem PNG/JPEG de cada página (sharp ou pdftoppm).

OCR heurístico (opcional) para sugerir labels e detectar caixas (tesseract ou heurísticas de layout).

Gerar template.json inicial com bounding boxes aproximadas.

UI Calibrator: operador arrasta/ajusta posições e salva a versão final.

Salvar pdf_path + template_json no sinan_templates.

Observação: o OCR só sugere — a calibração manual final é recomendada para garantir pixel-perfect.

6 — UI: FormRenderer (conceito + snippet React)

Rende a imagem de fundo (o PDF convertido em PNG) e posiciona inputs absolutizados.

Inputs acompanham zoom/scroll.

Exemplo simplificado (React + CSS absolute):

// FormRenderer.tsx (simplified)
import React from "react";

export function FormRenderer({ template, payload, onChange }) {
  const { pageImage, fields } = template;
  return (
    <div style={{ position: "relative", width: template.pageSize.width }}>
      <img src={pageImage} style={{ width: "100%", display: "block" }} />
      {fields.map(f => (
        <input
          key={f.id}
          value={payload[f.id] || ""}
          onChange={e => onChange(f.id, e.target.value)}
          style={{
            position: "absolute",
            left: (f.x / template.pageSize.width) * 100 + "%",
            top: (f.y / template.pageSize.height) * 100 + "%",
            width: (f.width / template.pageSize.width) * 100 + "%",
            height: f.height,
            fontSize: f.fontSize
          }}
          required={f.required}
        />
      ))}
    </div>
  );
}


O TemplateCalibrator permite selecionar um campo, arrastar/resize e salvar coordenadas.

8 — Geração PDF idêntico (técnica)

Use pdf-lib:

Carrega o PDF template original (não rasterizar);

Escreve texto nas coordenadas (x,y) convertidas para PDF points;

Embute TTF se necessário para conservar fontes;

Gera um PDF final visualmente idêntico.

Se o template usar campos mão-escrita, manter a imagem original e apenas sobrepor texto posicionado exatamente.

Trecho de exemplo (node + pdf-lib):

import { PDFDocument, rgb } from 'pdf-lib';
import fs from 'fs';

async function fillPdf(templatePath, outputPath, templateJson, payload) {
  const existingPdfBytes = fs.readFileSync(templatePath);
  const pdfDoc = await PDFDocument.load(existingPdfBytes);
  const pages = pdfDoc.getPages();
  const page = pages[0];
  const { width, height } = page.getSize();
  // embed font if needed...
  for(const f of templateJson.fields){
    const value = payload[f.id] || '';
    page.drawText(value, {
      x: f.x,
      y: height - f.y - f.height, // converter coordenadas
      size: f.fontSize
    });
  }
  const pdfBytes = await pdfDoc.save();
  fs.writeFileSync(outputPath, pdfBytes);
}

9 — Validação server-side (regras principais)

Campos obrigatórios do template.json devem existir.

Validadores comuns:

CPF (mod11), CNS, IBGE município (7 dígitos), datas (YYYY-MM-DD), CID format.

Regras condicionais (ex.: se procedimento exige APAC → APAC fields required).

Rejeitar envio e retornar missing + warnings até que tudo válido.

10 — Dedupe leve antes de enviar

Check 1: CPF/CNS exact

Check 2: name normalized + DOB + município

Check 3: fuzzy name + DOB (Levenshtein)

Se possível duplicate → criar possible_duplicates entry e notificar vigilância para revisão. Não sobrescrever registros.

11 — Alertas e prazos

Alerta de pendência: se ficha enviada e NÃO aprovada em X horas → push/email + badge.

Prazos config: 72h / 48h / 24h before deadline.

Alertas de risco financeiro (ex.: Previne indicador baixo) baseados em relatórios gerados.

12 — Relatórios que ajudam captação de recursos

Relatório Previne: campos completude; porcentagem de famílias com cadastro atualizado; cobertura vacinal; gestantes com 6 consultas — export CSV para prestar contas ou justificar demanda.

Relatório MAC/AIH: produção por unidade, lista de AIH com risco de glosa (documentos faltantes).

Relatório vigilância: notificações por agravo, duplicatas, prazos vencidos (útil para justificar necessidade de recursos).

Relatório SUAS+Saúde: famílias vulneráveis sem acompanhamento (base para projetos com MDS, Criança Feliz, emendas).

13 — QA / checklist antes do rollout

Templates calibrados manualmente (pelo menos 1 template por tipo testado).

Testes unitários de validação passados.

E2E: preencher → validar → enviar → aprovar → baixar PDF (Playwright).

Testes de geração de PDF em diferentes navegadores/visualizadores.

Treinamento mínimo dos usuários (documentação + vídeo 5–7 min).

Feature flag por unidade ENABLE_FORMS_TEMPLATES para rollout gradual.
