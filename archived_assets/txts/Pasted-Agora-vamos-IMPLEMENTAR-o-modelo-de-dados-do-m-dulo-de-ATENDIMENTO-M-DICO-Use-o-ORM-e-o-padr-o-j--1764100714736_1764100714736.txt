Agora vamos IMPLEMENTAR o modelo de dados do módulo de ATENDIMENTO MÉDICO.

Use o ORM e o padrão já usados no projeto (Prisma, Drizzle, TypeORM etc.).

Crie as tabelas/entidades abaixo, respeitando:
- Multi-tenant (sempre incluir tenant_id ou campo equivalente usado no projeto)
- Relacionamento com:
  - Paciente (tabela já existente)
  - Profissional de saúde (tabela já existente)
  - Unidade/Equipe (se existir esse relacionamento no sistema)

1. Tabela/entidade: medical_encounters (atendimentos médicos)
   Campos sugeridos:
   - id (PK)
   - tenant_id
   - patient_id (FK)
   - professional_id (FK)
   - team_id ou unit_id (se o projeto usar isso)
   - status (enum: 'EM_ANDAMENTO', 'FINALIZADO', 'CANCELADO')
   - motivo_consulta (texto)
   - historia_clinica (texto)
   - exame_fisico (texto)
   - observacoes_gerais (texto opcional)
   - data_hora_inicio
   - data_hora_fim
   - created_at
   - updated_at

2. Tabela/entidade: medical_diagnoses
   - id
   - tenant_id
   - encounter_id (FK medical_encounters)
   - codigo (string)  // pode ser CIAP-2 ou CID-10
   - tipo (enum: 'CIAP', 'CID')
   - descricao (texto opcional)
   - principal (boolean)

3. Tabela/entidade: medical_prescriptions
   - id
   - tenant_id
   - encounter_id (FK)
   - medicamento (string)  // DCB ou nome de exibição
   - dose (string)
   - via (string)
   - frequencia (string)
   - duracao (string)
   - observacoes (texto opcional)

4. Tabela/entidade: medical_exam_requests
   - id
   - tenant_id
   - encounter_id (FK)
   - tipo_exame (string)
   - observacoes (texto opcional)
   - prioridade (string ou enum)

5. Tabela/entidade: medical_procedures
   - id
   - tenant_id
   - encounter_id (FK)
   - procedimento (string)
   - codigo_procedimento (string opcional)
   - observacoes (texto opcional)

6. Tabela/entidade: medical_referrals
   - id
   - tenant_id
   - encounter_id (FK)
   - destino (string)  // ex: "CAPS", "Ortopedia", "Cardiologia", "UPA"
   - motivo (texto)
   - prioridade (string ou enum)
